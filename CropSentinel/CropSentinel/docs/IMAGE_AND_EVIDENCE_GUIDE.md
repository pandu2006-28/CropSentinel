# Images and evidence guide

## Concept visuals
Concept renders and diagrams can explain proposed design. Label them “Concept illustration — not fabricated hardware.” Do not use them as build evidence.

## Genuine maker evidence
As work happens, add real, dated photos/screenshots:
- `evidence/01_components/` — actual components and visible part markings
- `evidence/02_bench_tests/` — real test setup and serial output
- `evidence/03_assembly/` — actual assembly/wiring
- `evidence/04_receiver/` — receiver states and alert UI
- `evidence/05_validation/` — test setup and measured results

Each item should state date, setup, purpose, result and limitations. Obtain consent before photographing people/property. Avoid unnecessary personal or precise-location data. Never use stock or AI-generated images as proof a physical prototype was built, or falsify timestamps/logs.
